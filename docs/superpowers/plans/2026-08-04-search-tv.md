# Search TV Implementation Plan

> **Execution rule:** implement this as one bounded product slice over accepted Search Core. Do not introduce a second search store, global state architecture, Paging, fuzzy/vector search or a custom TV keyboard.

**Goal:** Replace the Search placeholder with a remote-first Android TV screen that queries accepted `ChannelSearchRepository`, cancels stale input, preserves canonical focus across Player/Back and refreshes current-programme matches at the repository-provided boundary.

**Architecture:** `:feature:search` owns destination-scoped presentation state and Compose UI. It depends only on public catalog/design contracts. `:app:tv` supplies the repository and profile through the existing explicit Navigation3 route composition. Room and FTS stay behind `ChannelSearchRepository`.

**Tech stack:** Kotlin 2.3, Coroutines/Flow, Compose Foundation, Compose for TV Material, Lifecycle ViewModel, Navigation3, Room-backed `ChannelSearchRepository`.

## Global constraints

- Start the final PR from the accepted post-ownership `main`; this work branch is implementation staging only.
- Keep repository result bounds: default 100, hard maximum 200.
- Never filter the complete catalog or guide in Compose memory.
- Use canonical `channelId` for item identity and restoration.
- Do not log query text, channel/programme labels, locators, headers or provider identity.
- Use the system TV IME; no custom keyboard.
- `OK` on a result opens the existing Player directly.
- No Room schema change.

### State contract

- `Idle`: blank normalized query; repository is not invoked.
- `Loading`: nonblank debounced query is being observed.
- `Content`: bounded rows + truncation flag.
- `Empty`: nonblank query returned no rows.
- `Failed`: current query collection failed; no exception/provider text reaches UI.

Each row contains only current surface data:

- canonical channel ID;
- number/name/group;
- favorite flag;
- variant count;
- current programme title when present.

### Query pipeline

1. Accept immediate user text into a `StateFlow`.
2. Normalize whitespace through `ChannelSearchQuery` at repository-boundary construction.
3. Debounce text changes for 275 ms.
4. Apply `distinctUntilChanged` to normalized query values.
5. Combine with an internal boundary-refresh generation.
6. Use `flatMapLatest` so a new query cancels the old repository collection.
7. Convert repository snapshots into explicit UI states.
8. Schedule one cancellable boundary job from `nextBoundaryEpochMillis`; when due, increment refresh generation and rebuild the same query with a fresh `nowEpochMillis`.
9. Cancel boundary work on blank input, new query, failure and ViewModel clear.

### Unit acceptance

- blank query produces `Idle` and zero repository requests;
- typing within 275 ms produces only the final request;
- newer query cancels the previous repository flow;
- rows/truncation are projected correctly;
- empty and failure states are explicit;
- boundary triggers exactly one refresh with newer time;
- changing query cancels the previous boundary timer;
- ViewModel diagnostics/state `toString` do not expose user text.

**Files:**
- Create: `feature/search/src/main/kotlin/app/muxtv/feature/search/SearchRoute.kt`
- Create: `feature/search/src/main/kotlin/app/muxtv/feature/search/SearchFocus.kt`
- Test: `feature/search/src/test/kotlin/app/muxtv/feature/search/SearchFocusTest.kt`

### Layout

- one large system-IME text field at the top;
- one compact status/count line;
- one full-width `LazyColumn` of channel results;
- no poster grid, preview panel or second content column;
- idle/loading/empty/error copy remains focus-safe and secret-free.

### D-pad/focus

- initial focus enters the search field;
- Down from the field enters the first result when available;
- Up from the first result returns to the field;
- each result has a stable `FocusRequester` keyed by canonical channel ID;
- capture `SearchFocusAnchor(channelId, previousIndex, scrollOffset)` when focused/opened;
- on return or result invalidation, resolve the exact surviving ID, otherwise nearest previous index;
- wait for the exact key/index pair to be placed before requesting focus, matching the accepted Channels pattern;
- return focus to the input when results disappear or the current request fails;
- focus state does not resize neighbouring rows.

### UI acceptance

- long Russian/Cyrillic names retain row geometry;
- number/name/group/current programme are truncated deterministically;
- favourite/current-programme markers do not change layout on focus;
- truncation is disclosed without claiming completeness;
- query and focused result survive Search → Player → Back through existing Navigation3 decorators.
