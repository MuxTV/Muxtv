# MuxTV 0.1.0-alpha.1

MuxTV `0.1.0-alpha.1` is an early local-first Android TV build for testing the core IPTV experience with user-provided sources. It does not include channels or subscriptions and does not broaden compatibility claims beyond the evidence recorded for this release candidate.

## Alpha scope

The alpha scope is trustworthy Live TV: add an authorized IPTV source, publish a bounded local catalog and EPG, browse Channels/Search/Guide, and play through the single service-owned Media3 playback path with bounded recovery and secret-safe diagnostics.

This release is intended for controlled alpha qualification rather than general production distribution. Features or provider dialects that are not part of the exact accepted release tree are not implied by these notes.

## Known limitations

- Canonical virtual correctness is exercised on Android TV API26 and API36. These emulator gates validate Android contracts but do not establish hardware-wide codec, HDR, audio-passthrough, thermal or absolute-performance support.
- physical TV qualification is separate and device-scoped. A result on one device must not be generalized to other SoCs, vendors or firmware versions.
- Fire TV qualification is availability-conditional and remains separate from generic Android TV emulator evidence.
- Baseline Profile packaging and execution are evidenced, but the current hosted-emulator comparison is `LIMITED_EVIDENCE`; it does not establish a reproducible material startup improvement on physical hardware.
- release signing remains a required distribution gate. Unsigned or signer-unverified artifacts are evidence inputs, not distributable release artifacts.
- Provider/server-specific archive, codec and transport behavior is supported only where separately characterized and accepted; these notes make no blanket provider compatibility claim.

## Recovery

If the app is not behaving as expected:

1. Open Doctor and review the redacted diagnostic state; do not copy private source locators or provider secrets into public reports.
2. Retry the affected source refresh after checking network access and the source configuration.
3. If local application state is unrecoverable and no retained previous-good state can be restored, use Android Settings to clear app data, then add the source again. This removes local application data and credentials, so it is a last-resort recovery action.

Recovery reports should identify the app version, exact source commit when known, device/API class and the stable redacted error category. They should not contain usernames, passwords, authorization values, playlist URLs or generated provider transports.

## Evidence boundaries

Release readiness is owned by #31 and remains fail-closed. Evidence is valid only for the exact candidate commit/artifact to which it is attached.

- API26/API36 virtual results are `VERIFIED_VIRTUAL` platform evidence only.
- A named physical TV result may be `VERIFIED_PHYSICAL_DEVICE` only for that recorded hardware and configuration.
- Fire TV, vendor codec/HDR/audio behavior and weak-device performance remain `UNVERIFIED` unless separate physical evidence exists for the candidate.
- Baseline Profile startup measurements remain `LIMITED_EVIDENCE` until repeatable physical-device before/after measurements justify a stronger claim.
- SBOM, provenance, reproducibility and license evidence do not substitute for release signing or physical playback qualification.

Do not distribute `0.1.0-alpha.1` as a signed alpha until every required #31 distribution gate for the selected candidate is satisfied.
