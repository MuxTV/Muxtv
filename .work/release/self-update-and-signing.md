# Self-update, signing and release trust

## 1. Scope

MuxTV распространяется вне Google Play через GitHub Releases. Android package signature является корнем доверия установки; GitHub metadata/checksum дополняют, но не заменяют её. Обновление всегда подтверждается системным PackageInstaller, если приложение не работает как device/profile owner.

## 2. Stable identity

До первого публичного APK фиксируются:

```text
applicationId: app.muxtv.tv
release signing lineage
versionCode policy
release repository: MuxTV/Muxtv
stable update channel identifier
```

Изменение applicationId после распространения создаёт новое приложение и не является обычной миграцией.

## 3. Signing key

- release key генерируется вне репозитория;
- private key не хранится в GitHub source, Actions artifacts, `.work` или developer machines без защищённого процесса;
- CI secret минимально доступен только protected release environment либо signing выполняется отдельно;
- сохраняются encrypted offline backups и documented recovery ownership;
- certificate SHA-256 публикуется в repository docs/releases;
- debug/nightly APK использует другую applicationId/signing identity и не обновляет stable installation;
- key rotation использует Android signing lineage только после отдельной tested procedure;
- утрата/компрометация ключа имеет incident plan.

## 4. Versioning

Semantic version and Android versionCode separate:

```text
0.1.0-alpha.1 → human release/tag
versionCode     → monotonically increasing integer
```

Channels:

- `stable`;
- `beta` — opt-in;
- `nightly` — separate applicationId, not in-app channel switch.

Stable updater ignores prereleases unless current profile/installation explicitly opted into beta.

Downgrade rejected by default. Recovery downgrade requires manual sideload/uninstall-aware flow and backup warning.

## 5. Release assets

Initial assets:

```text
muxtv-stable-universal.apk
muxtv-stable-arm64-v8a.apk       optional after size evidence
muxtv-stable-armeabi-v7a.apk     optional if supported
checksums-sha256.txt
release-metadata.json
SBOM (CycloneDX or SPDX)
source archive generated by GitHub
release notes
```

Prefer universal APK for mass-user simplicity until ABI split yields meaningful size/startup benefit. Asset naming and metadata are stable machine contracts.

## 6. Release metadata

Signed/verified logical schema:

```json
{
  "schemaVersion": 1,
  "channel": "stable",
  "versionName": "0.1.0",
  "versionCode": 10000,
  "applicationId": "app.muxtv.tv",
  "minSdk": 26,
  "publishedAt": "...",
  "commit": "...",
  "assets": [
    {
      "name": "muxtv-stable-universal.apk",
      "abi": "universal",
      "sha256": "...",
      "size": 0,
      "certificateSha256": "..."
    }
  ]
}
```

Metadata fetched only from official release/tag context. The app does not accept arbitrary update URL from playlist, QR or extension.

## 7. Update check

1. verify installed build channel and package identity;
2. fetch cached/conditional official release metadata;
3. reject draft/unexpected prerelease/channel;
4. parse bounded schema;
5. compare versionCode;
6. select compatible asset;
7. display version/size/release notes/security warning if needed;
8. download only after user action or approved auto-download setting;
9. verify length/hash/package/certificate;
10. invoke PackageInstaller and let user/system approve;
11. after update, run migration/health startup and record result.

Update check failure never blocks playback.

## 8. APK verification

Before PackageInstaller:

- SHA-256 matches metadata/checksum;
- APK parses successfully;
- package name matches current installation;
- versionCode is greater than installed;
- signing certificate/lineage matches trusted digest;
- minSdk/device compatibility valid;
- asset not truncated;
- expected TV launcher declaration can be checked as defense-in-depth;
- no request to install different package from stable updater.

Android PackageInstaller/package manager performs final signature/update validation. MuxTV verification provides earlier actionable failure and supply-chain defense.

## 9. Download

- app-private cache/temp file;
- resumable only when server/range/ETag safely support it;
- bounded disk space check;
- metered-network policy;
- foreground/user-visible progress for user-initiated large transfer;
- cancellation and cleanup;
- no executable permission/use before verification;
- asset URL redirects undergo update-specific allowlist validation;
- file removed after successful install or retention timeout.

## 10. User experience

Update card:

```text
MuxTV 0.2.0 доступна
Размер: 28 МБ
Основное: ...
[Скачать и установить] [Позже] [Подробнее]
```

- no forced update except separately documented critical unsupported-version policy;
- no deceptive custom installer UI;
- user receives system prompt;
- unknown-sources permission guidance appears only when required;
- updater reports exact failure: checksum, certificate, package mismatch, insufficient storage, installation denied;
- release notes available before download;
- playback not interrupted until user starts installation.

## 11. Migration and rollback safety

Before update:

- database schema compatibility declared in release metadata/build;
- automatic local backup/checkpoint for risky migrations;
- migration tests from all supported versions;
- interrupted migration must fail safely;
- app retains previous catalog revision where feasible;
- rollback of APK is not assumed possible after forward-only DB migration;
- release can be pulled from updater feed, but already installed app must remain functional/offline.

A migration that cannot support rollback requires explicit release note and verified backup/restore path.

## 12. GitHub Actions security

Release workflow:

- manual/tag/protected trigger;
- minimal `permissions` per job;
- third-party actions pinned to immutable commit SHA;
- wrapper validation;
- dependency review/secret scan;
- clean build and tests;
- SBOM/checksum generation in same controlled pipeline;
- release environment approval for signing/publishing;
- no untrusted PR code receives signing secrets;
- artifacts retained according to policy;
- generated metadata tied to exact commit;
- release creation idempotent and rejects existing versionCode/tag conflicts.

## 13. Reproducible builds

Target:

- pinned Gradle wrapper/toolchain/dependencies;
- deterministic resources/archive timestamps where supported;
- no build-time current timestamps inside APK except explicit reproducible metadata;
- compare unsigned/intermediate or final APK under controlled environment;
- document unavoidable nondeterminism;
- publish build instructions and checksums.

GitHub artifact attestations may be used when plan/repository visibility supports them, but MuxTV does not depend solely on a feature unavailable for the current private repository/account tier.

## 14. Incident response

### Bad release

- mark release withdrawn;
- updater feed points to last safe/new hotfix, never lower versionCode silent downgrade;
- publish advisory and recovery steps;
- preserve artifacts/logs for analysis.

### Signing key suspected compromised

- stop releases;
- verify affected certificate lineage/assets;
- rotate through supported lineage if feasible;
- publish advisory through independent project channels;
- do not train users to install APK signed by unrelated certificate as an «update».

### GitHub/repository compromise

- certificate validation prevents normal in-place malicious update signed by attacker without key;
- revoke compromised automation credentials;
- audit releases/tags/workflows;
- re-establish protected pipeline.

## 15. Android developer verification

MuxTV tracks Android's developer verification rollout separately from Google Play publication. Package name and signing identity are fixed early; required registration procedures may be added without changing the open-source/GitHub distribution model. Documentation is reviewed before affected regional/global enforcement dates.

## 16. Tests

- release metadata parser fuzz/bounds;
- wrong repo/channel/prerelease;
- wrong package name;
- lower/equal versionCode;
- wrong certificate and broken signing lineage;
- checksum/truncation mismatch;
- redirect outside allowed release infrastructure;
- insufficient disk/cancel/resume/process death;
- PackageInstaller user deny/cancel;
- upgrade migration from every supported schema;
- stable/beta/nightly separation;
- release workflow cannot expose signing secrets to PR;
- reproducibility comparison.

## 17. Acceptance criteria

- only official MuxTV package/certificate can be offered as in-place update;
- user/system confirmation remains mandatory;
- wrong hash/certificate/package/downgrade is rejected before installation;
- GitHub outage does not block normal app use;
- signing secret never reaches untrusted workflow;
- release artifact is traceable to commit/toolchain/SBOM;
- migration failure has documented recovery;
- nightly build cannot overwrite stable installation.
